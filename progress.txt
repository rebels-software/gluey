## [US-006] - Implement DSL parser - routing and error handling - 2026-01-29

### Implementation
- Extended Parser.cs with routing and error handling support:
  - `| route { name: condition }` - route blocks with multiple conditions
  - `name -> <output>("config")` - route destination mapping
  - `name -> [ output1, output2 ]` - multiple outputs per route
  - `on_error: skip` - skip on error
  - `on_error: route_to("name")` - route to error queue
  - `*` as catch-all route condition
- Key parsing methods added:
  - `ParseRouteConditionsBlock()` - parses route block with expression conditions
  - `ParseExpression()` - captures expression tokens until terminator
  - `ParseRouteDestination()` - parses `name -> output(...)` syntax
  - `ParseOutputDestination()` - parses output with config
  - `CheckAhead()` - lookahead helper for detecting patterns
- Route conditions and destinations are merged by name during parsing
- Added unit tests to verify all routing scenarios

### Files Modified

- tests/Gluey.Parser.Tests/RouteParsingTests.cs (new - 8 tests)
- tests/Gluey.Parser.Tests/Gluey.Parser.Tests.csproj (added Gluey.Parser reference)

### Learnings
- Route blocks define conditions but not destinations; destinations are defined separately with `->` syntax
- Expression parsing requires careful termination detection: stop on `}`, `,`, or `identifier:` patterns

## [US-011] - Implement WorkflowRunner - 2026-01-29

### Implementation
- Completed WorkflowRunner.cs in Gluey.Runtime with full pipeline execution:
  - RunAsync reads messages from input plugin via IAsyncEnumerable
  - Applies each transform in sequence to the message

## [US-013] - Implement HttpWebhookInput plugin - 2026-01-29

### Implementation
- Created HttpWebhookInput.cs in Gluey.Plugins/Inputs/ implementing IInputPlugin
- Uses Kestrel minimal API with WebApplication.CreateSlimBuilder
- Listens on configured port (default: 8080) and path (default: /webhook)
- Accepts POST requests with JSON or binary body
- Handles Content-Type: application/json by parsing JSON directly to JsonDocument
- Handles Content-Type: application/octet-stream by storing bytes as base64 in metadata
- Unknown content types wrapped as {"data": "..."} JSON object
- Uses Channel<Message> for async message queueing (unbounded, single-reader)
- Implements IAsyncDisposable for proper cleanup
- Returns HTTP 200 OK on success, 500 on error
- Server runs in background task started during InitializeAsync

### Files Modified
- src/Gluey.Plugins/Inputs/HttpWebhookInput.cs (new - 183 lines)
- src/Gluey.Plugins/Gluey.Plugins.csproj (added FrameworkReference to Microsoft.AspNetCore.App, Gluey.Core reference)

- src/Gluey.Runtime/PluginRegistry.cs (registered HttpWebhookInput in RegisterBuiltInPlugins)
- src/Gluey.Runtime/Gluey.Runtime.csproj (added Gluey.Plugins reference)

### Learnings
- Use FrameworkReference instead of PackageReference for Microsoft.AspNetCore.App in .NET 10
- WebApplication.CreateSlimBuilder(args) accepts --urls command-line arg for port configuration
- Channel<T> is perfect for bridging HTTP requests (push) to IAsyncEnumerable (pull) patterns
- UnboundedChannelOptions with SingleReader/SingleWriter optimizes channel performance
- Binary payloads stored as base64 in metadata since Message.Payload requires JsonDocument
- ConfigureKestrel/UseUrls extensions not available on ConfigureWebHostBuilder in minimal hosting
- RunAsync blocks until cancellation, so must run in background Task to avoid blocking InitializeAsync
