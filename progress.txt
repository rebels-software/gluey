## [US-003] - Define plugin interfaces - 2026-01-29

### Implementation
- Created 3 plugin interfaces in Gluey.Core/Abstractions/:
  - IInputPlugin: Type property, InitializeAsync, ReadAsync (IAsyncEnumerable<Message>), IAsyncDisposable
  - ITransformPlugin: Type property, InitializeAsync, ProcessAsync (returns Message or null for filtering)
  - IOutputPlugin: Type property, InitializeAsync, WriteAsync, IAsyncDisposable

### Files Modified
- src/Gluey.Core/Abstractions/IInputPlugin.cs (new)
- src/Gluey.Core/Abstractions/ITransformPlugin.cs (new)
- src/Gluey.Core/Abstractions/IOutputPlugin.cs (new)

### Learnings
- IInputPlugin and IOutputPlugin implement IAsyncDisposable for resource cleanup (connections, listeners)
- ITransformPlugin does not need disposal as transforms are typically stateless
- Config type uses `IReadOnlyDictionary<string, JsonElement>` to match PipelineStep.Config
- ProcessAsync returns `Message?` - null signals message should be filtered/dropped from pipeline

## [US-004] - Implement DSL lexer - 2026-01-29

### Implementation
- Created Lexer.cs in Gluey.Parser with:
  - TokenType enum: keywords (flow, from, route, on_error, schema, migrate, filter, transform, enrich, description), literals (string, number, true, false, null), identifiers, all symbols, operators
  - Token record: Type, Value, Line, Column for error reporting
  - Lexer class: hand-rolled recursive descent lexer with full tokenization support
- Features implemented:
  - Keywords: flow, from, route, on_error, schema, migrate, filter, transform, enrich, description
  - Symbols: { } [ ] ( ) | : -> , . ?
  - Operators: && || == != > < >= <= + - * / & ^ !
  - Literals: double/single quoted strings with escape sequences, numbers (int, float, hex 0x), booleans
  - Identifiers: standard alphanumeric + underscore naming
  - Comments: // single-line and /* */ multi-line
  - Whitespace handling with line/column tracking
- Removed placeholder Class1.cs

### Files Modified
- src/Gluey.Parser/Lexer.cs (new - 466 lines)
- src/Gluey.Parser/Class1.cs (deleted)

### Learnings
- Used sealed record for Token for immutability and value equality
- Keywords dictionary is case-insensitive (StringComparer.OrdinalIgnoreCase)
- Dotted names (json.parse, decode.binary) are tokenized as separate Identifier and Dot tokens - the parser will combine them
- Line/column tracking is critical for good error messages
- StringBuilder used for string and number scanning for efficiency
